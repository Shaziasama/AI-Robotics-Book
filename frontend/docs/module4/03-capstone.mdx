## Bringing it All Together: The Autonomous Humanoid

Throughout this book, you have built foundational knowledge in ROS 2, simulated physics and sensors in Gazebo and Unity, leveraged NVIDIA Isaac for advanced perception and simulation, and integrated Large Language Models (LLMs) for cognitive planning and voice command understanding. This Capstone Project is designed to synthesize all these concepts, challenging you to integrate these diverse components into a single, cohesive system: an autonomous humanoid robot.

The goal is to create a humanoid that can:
1.  **Understand natural language commands** via voice.
2.  **Translate these commands into executable robot actions** using an LLM.
3.  **Navigate autonomously** in a simulated environment using perception (from simulated sensors) and planning.
4.  **Perform basic interaction tasks** (e.g., approach an object, identify it).
5.  **Maintain balance and stability** using its bipedal locomotion.

This project will demonstrate the full Vision-Language-Action (VLA) pipeline in action, illustrating how digital intelligence can be physically embodied in a humanoid robot.

## Project Overview: A Simple "Fetch the Object" Scenario

We will aim for a simplified "fetch the object" scenario in a simulated environment (preferably Isaac Sim or Gazebo, depending on your preference and hardware capabilities).

**Scenario:**
A human user verbally commands the humanoid robot to "Go find the blue cube" or "Pick up the red ball." The humanoid should:
1.  Hear and understand the command.
2.  Plan a path to the object.
3.  Navigate to the object.
4.  Identify the object (e.g., its color).
5.  (Optional but advanced) Attempt a "grasp" action.

## Integration Plan: Connecting the Modules

This project requires careful integration of the components developed in previous modules.

```mermaid
graph TD
    A[Human Voice] --> B(Module 4.1: Whisper STT)
    B --> C{LLM Planner: Module 4.2}
    C -- Action Plan (JSON) --> D[Action Executor (New Node)]
    D -- ROS 2 Commands --> E[Humanoid Control Stack]
    E -- Joint Commands --> F[Simulated Humanoid Robot (Isaac Sim/Gazebo)]
    F --> G[Simulated Sensors (Camera, LiDAR, IMU)]
    G --> H[Module 3.2: Isaac ROS VSLAM / Nav2 Localization]
    H --> C
    H --> E
```

### Key Integration Points:

1.  **Voice Command to LLM:**
    *   Whisper node publishes `std_msgs/String` to `/voice_commands`.
    *   LLM Planner node subscribes to `/voice_commands`, sends to LLM, and publishes action plan to `/robot_action_plan` (as `std_msgs/String` containing JSON).

2.  **Action Executor:**
    *   A new ROS 2 node that subscribes to `/robot_action_plan`.
    *   Parses the JSON action plan.
    *   Translates high-level actions (e.g., `MOVE_TO(x, y)`, `GRASP(object)`) into sequences of ROS 2 messages for navigation (e.g., `geometry_msgs/Twist`) and manipulation (e.g., service calls to a grasping controller).

3.  **Navigation Stack:**
    *   Utilize Nav2 (Module 3.3) for global and local path planning.
    *   Localization provided by Isaac ROS VSLAM (Module 3.2) or AMCL (from Nav2).
    *   The Action Executor sends goals to Nav2 (via `action_server`) or directly publishes `cmd_vel` to the humanoid's walking controller.

4.  **Perception for Object Recognition:**
    *   Simulated camera data (Module 2.2 / Module 3.1) is used by a perception node.
    *   A simple object detection model (e.g., color-based, or a pre-trained deep learning model) identifies the target object's pose. This could be trained using synthetic data from Isaac Sim.

5.  **Humanoid Control:**
    *   The humanoid's walking controller (Module 3.3) translates `cmd_vel` into bipedal locomotion.
    *   A grasping controller (if implemented, beyond scope of this chapter for full detail) would execute manipulation actions.

### 3. Implement the Action Executor Node

This is a new node that ties the LLM's plan to the robot's capabilities.

Create `capstone_ws/src/humanoid_vla/humanoid_vla/action_executor_node.py`:

```python
import rclpy
from rclpy.node import Node
from std_msgs.msg import String
from geometry_msgs.msg import Twist
import json
import time

# --- Configuration ---
ACTION_PLAN_TOPIC = "/robot_action_plan"
CMD_VEL_TOPIC = "/cmd_vel"
# --- End Configuration ---

class ActionExecutor(Node):
    def __init__(self):
        super().__init__('action_executor')
        self.subscription = self.create_subscription(
            String,
            ACTION_PLAN_TOPIC,
            self.action_plan_callback,
            10)
        self.subscription
        self.cmd_vel_publisher = self.create_publisher(Twist, CMD_VEL_TOPIC, 10)
        self.get_logger().info(f'Action Executor node started, subscribing to {ACTION_PLAN_TOPIC}.')

    def execute_move_forward(self, distance_m):
        self.get_logger().info(f"Executing: MOVE_FORWARD {distance_m} meters")
        twist = Twist()
        twist.linear.x = 0.2 # Constant forward velocity
        start_time = self.get_clock().now().seconds_nanoseconds()[0]
        duration = distance_m / twist.linear.x # Time to cover distance
        
        while (self.get_clock().now().seconds_nanoseconds()[0] - start_time) < duration:
            self.cmd_vel_publisher.publish(twist)
            time.sleep(0.1) # Small delay
            rclpy.spin_once(self, timeout_sec=0.1)
        
        # Stop the robot
        twist.linear.x = 0.0
        self.cmd_vel_publisher.publish(twist)
        self.get_logger().info("MOVE_FORWARD completed.")

    def execute_turn(self, angle_deg):
        self.get_logger().info(f"Executing: TURN {angle_deg} degrees")
        twist = Twist()
        angular_speed = 0.5 # radians/sec
        if angle_deg > 0:
            twist.angular.z = angular_speed
        else:
            twist.angular.z = -angular_speed
        
        duration = abs(angle_deg * (np.pi / 180.0)) / angular_speed # Time to turn
        start_time = self.get_clock().now().seconds_nanoseconds()[0]
        
        while (self.get_clock().now().seconds_nanoseconds()[0] - start_time) < duration:
            self.cmd_vel_publisher.publish(twist)
            time.sleep(0.1)
            rclpy.spin_once(self, timeout_sec=0.1)
        
        # Stop the robot
        twist.angular.z = 0.0
        self.cmd_vel_publisher.publish(twist)
        self.get_logger().info("TURN completed.")

    def execute_stop(self):
        self.get_logger().info("Executing: STOP")
        twist = Twist() # All zeros
        self.cmd_vel_publisher.publish(twist)
        self.get_logger().info("STOP completed.")

    def execute_grasp(self, object_id):
        self.get_logger().info(f"Executing: GRASP {object_id}")
        # In a real system, this would trigger a manipulation action or service call
        self.get_logger().info(f"Simulating grasp of {object_id}. (Requires actual manipulation controller)")
        time.sleep(2) # Simulate grasp time
        self.get_logger().info("GRASP completed.")

    def action_plan_callback(self, msg):
        self.get_logger().info(f"Received action plan: '{msg.data}'")
        try:
            plan = json.loads(msg.data)
            action = plan.get("action")
            parameters = plan.get("parameters", {})

            if action == "MOVE_FORWARD":
                self.execute_move_forward(parameters.get("distance_m", 0.0))
            elif action == "TURN":
                self.execute_turn(parameters.get("angle_deg", 0.0))
            elif action == "STOP":
                self.execute_stop()
            elif action == "GRASP":
                self.execute_grasp(parameters.get("object_id", "unknown"))
            else:
                self.get_logger().warn(f"Unknown action: {action}")
        except json.JSONDecodeError as e:
            self.get_logger().error(f"Failed to parse action plan JSON: {e}")
        except Exception as e:
            self.get_logger().error(f"Error executing action: {e}")

def main(args=None):
    rclpy.init(args=args)
    action_executor = ActionExecutor()
    rclpy.spin(action_executor)
    action_executor.destroy_node()
    rclpy.shutdown()

if __name__ == '__main__':
    main()
```

## Troubleshooting Common Integration Issues

*   **Topic Mismatches:** Ensure all nodes are publishing/subscribing to the correct topic names and message types.
*   **Coordinate Frames (TF):** Correctly define and publish `tf` transforms for all robot links and sensors to ensure proper localization and navigation.
*   **Performance:** Complex simulations and AI models can be resource-intensive. Monitor CPU/GPU usage and consider optimizations (e.g., smaller Whisper models, downsampling images, optimizing LLM calls).
*   **LLM Prompt Engineering:** The quality of the LLM's action plan heavily depends on the prompt. Experiment with different prompts to get reliable, structured outputs.
*   **Synchronization:** Ensure proper synchronization between sensor data, planning, and control loops (e.g., using `use_sim_time`).
