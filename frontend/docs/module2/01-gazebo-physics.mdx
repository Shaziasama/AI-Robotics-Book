## Introduction to Gazebo Simulation

Gazebo is a powerful 3D robot simulator that is widely used in the robotics community. It allows you to accurately and efficiently simulate complex robot scenarios in a virtual environment. With Gazebo, you can test algorithms, design robots, perform regression testing, and train AI systems using realistic physics, high-quality graphics, and convenient programmatic interfaces.

For humanoid robotics, Gazebo is invaluable. It enables you to:
*   Test balance and locomotion algorithms without risking damage to a physical robot.
*   Experiment with different sensor configurations and placements.
*   Simulate interactions with various environments and objects.
*   Generate large datasets for machine learning training.

### Key Components of a Gazebo Simulation

A Gazebo simulation typically involves several components:
*   **World:** Defines the environment, including terrain, objects, light sources, and physics properties (e.g., gravity).
*   **Robot Model:** Describes the physical characteristics of your robot, including its links, joints, sensors, and actuators (often defined using URDF or SDFormat).
*   **Physics Engine:** Calculates the motion and interactions of objects in the world. Gazebo supports several physics engines, such as ODE, Bullet, Simbody, and DART.
*   **Plugins:** Extend Gazebo's functionality, allowing for custom sensors, actuators, and control interfaces.

## Setting Up Your First Gazebo World with a Humanoid

Let's create a simple Gazebo world and load a basic humanoid model to observe its interaction with physics, gravity, and collisions.

### Prerequisites

*   A working ROS 2 installation (e.g., Humble or Iron).
*   Gazebo installed (`ros-<distro>-gazebo-ros-pkgs`, `ros-<distro>-gazebo-ros`).
*   A basic understanding of URDF (from Module 1).

### 1. Create a Gazebo World File

Gazebo worlds are defined using SDFormat (Simulation Description Format), which is an extension of XML.
Create a new file `my_humanoid_ws/src/humanoid_description/worlds/empty_humanoid_world.world`:

```xml
<?xml version="1.0" ?>
<sdf version="1.7">
  <world name="empty_humanoid_world">
    <!-- A global light source -->
    <include>
      <uri>model://sun</uri>
    </include>
    <!-- A ground plane -->
    <include>
      <uri>model://ground_plane</uri>
    </include>

    <!-- Physics Engine Configuration -->
    <physics type="ode">
      <max_step_size>0.001</max_step_size>
      <real_time_factor>1.0</real_time_factor>
      <real_time_update_rate>1000</real_time_update_rate>
      <ode>
        <solver>
          <type>quick</type>
          <iters>50</iters>
          <friction_model>cone</friction_model>
        </solver>
        <constraints>
          <cfm>0.0</cfm>
          <erp>0.2</erp>
          <contact_max_correcting_vel>100.0</contact_max_correcting_vel>
          <contact_surface_layer>0.001</contact_surface_layer>
        </constraints>
      </ode>
    </physics>

    <!-- Gravity -->
    <gravity>0 0 -9.81</gravity>

    <!-- Add your humanoid model here (will be loaded by a ROS 2 launch file) -->

  </world>
</sdf>
```

### 2. Prepare a Simple Humanoid URDF

For this example, let's assume you have a simple humanoid URDF (similar to the one from Module 1, or a pre-existing basic model). Ensure it's in a package accessible to ROS 2 (e.g., `humanoid_description/urdf/simple_humanoid.urdf`).

### 3. Create a ROS 2 Launch File to Spawn the Humanoid

Create `my_humanoid_ws/src/humanoid_bringup/launch/spawn_humanoid.launch.py`:

```python
import os
from ament_index_python.packages import get_package_share_directory
from launch import LaunchDescription
from launch.actions import DeclareLaunchArgument, IncludeLaunchDescription
from launch.launch_description_sources import PythonLaunchDescriptionSource
from launch.substitutions import LaunchConfiguration
from launch_ros.actions import Node

def generate_launch_description():
    # Get the launch directory
    humanoid_description_pkg = get_package_share_directory('humanoid_description')
    humanoid_bringup_pkg = get_package_share_directory('humanoid_bringup')
    gazebo_ros_pkg = get_package_share_directory('gazebo_ros')

    # Paths
    urdf_path = os.path.join(humanoid_description_pkg, 'urdf', 'simple_humanoid.urdf')
    world_path = os.path.join(humanoid_description_pkg, 'worlds', 'empty_humanoid_world.world')

    # Arguments
    use_sim_time = LaunchConfiguration('use_sim_time', default='true')

    # Nodes
    robot_state_publisher_node = Node(
        package='robot_state_publisher',
        executable='robot_state_publisher',
        parameters=[{'robot_description': open(urdf_path).read(), 'use_sim_time': use_sim_time}],
        output='screen'
    )

    joint_state_publisher_node = Node(
        package='joint_state_publisher',
        executable='joint_state_publisher',
        name='joint_state_publisher',
        parameters=[{'use_sim_time': use_sim_time}],
        output='screen'
    )

    gazebo_server_cmd = IncludeLaunchDescription(
        PythonLaunchDescriptionSource(os.path.join(gazebo_ros_pkg, 'launch', 'gazebo.launch.py')),
        launch_arguments={'world': world_path}.items()
    )

    gazebo_client_cmd = IncludeLaunchDescription(
        PythonLaunchDescriptionSource(os.path.join(gazebo_ros_pkg, 'launch', 'gazebo_client.launch.py'))
    )

    spawn_entity_cmd = Node(
        package='gazebo_ros',
        executable='spawn_entity.py',
        arguments=['-topic', 'robot_description', '-entity', 'simple_humanoid'],
        output='screen'
    )

    return LaunchDescription([
        DeclareLaunchArgument(
            'use_sim_time',
            default_value='true',
            description='Use simulation (Gazebo) clock if true'),
        robot_state_publisher_node,
        joint_state_publisher_node,
        gazebo_server_cmd,
        gazebo_client_cmd,
        spawn_entity_cmd,
    ])
```

### 4. Build and Launch

Ensure your URDF and launch files are in ROS 2 packages (`package.xml` and `setup.py`/`CMakeLists.txt` configured).

```bash
cd my_humanoid_ws
colcon build
source install/setup.bash

ros2 launch humanoid_bringup spawn_humanoid.launch.py
```

Gazebo should launch with the ground plane, sun, and your simple humanoid model. The humanoid will fall due to gravity and interact with the ground plane if not supported, demonstrating basic physics and collision.

:::tip Adjusting Physics Parameters
You can fine-tune the `<physics>` section in your `.world` file to experiment with different simulation speeds, accuracy, and contact behaviors. For example, `max_step_size` and `real_time_update_rate` are critical for balancing simulation fidelity with performance.
:::

## Understanding Collisions

Collisions in Gazebo are governed by the physics engine and the collision models defined in your robot's URDF.
*   **`<collision>` tag in URDF**: Defines the simplified geometric shapes (box, sphere, cylinder) used by the physics engine for collision detection. These are typically simpler than visual models to reduce computational load.
*   **Contact properties**: Gazebo can simulate friction, restitution (bounciness), and stiffness between colliding objects. These are often configured in the `.world` file or via Gazebo physics properties.

### Simulating a Dynamic Environment

Let's add a dynamic object to our world to see more complex collision responses.

### 1. Add a Dynamic Cube to the World File

Modify `empty_humanoid_world.world` to include a simple cube:

```xml
    <!-- Ground Plane already exists -->
    <include>
      <uri>model://ground_plane</uri>
    </include>

    <!-- Simple Dynamic Cube -->
    <model name="my_cube">
      <pose>0 0 1.0 0 0 0</pose> <!-- x y z roll pitch yaw -->
      <link name="cube_link">
        <inertial>
          <mass>1.0</mass>
          <inertia>
            <ixx>0.0016</ixx> <ixy>0</ixy> <ixz>0</ixz>
            <iyy>0.0016</iyy> <iyz>0</iyz> <izz>0.0016</izz>
          </inertia>
        </inertial>
        <visual name="cube_visual">
          <geometry><box><size>0.2 0.2 0.2</size></box></geometry>
          <material><ambient>0.8 0.1 0.1 1</ambient><diffuse>0.8 0.1 0.1 1</diffuse></material>
        </visual>
        <collision name="cube_collision">
          <geometry><box><size>0.2 0.2 0.2</size></box></geometry>
        </collision>
      </link>
    </model>

  </world>
</sdf>
```

### 2. Relaunch Gazebo

```bash
ros2 launch humanoid_bringup spawn_humanoid.launch.py
```

Now, when you launch, the red cube will fall and collide with the ground plane (and potentially your humanoid if it's placed appropriately). You can also interact with it using the Gazebo GUI controls (e.g., applying forces).
